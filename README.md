# PJT 일정 관리 시스템

React + TypeScript 프론트엔드와 Node/Express 백엔드로 구성된 프로젝트 일정(WBS) 관리 도구입니다.
데이터는 서버가 프로젝트별로 분리된 CSV 파일에 저장합니다.

## 구성

```
server/               Express API
  data/
    projects.csv       프로젝트 registry (id, name, description, createdAt, taskFile)
    tasks/
      <프로젝트명>.csv   프로젝트별 작업(Task) 데이터
client/                Vite + React + TypeScript SPA
```

## 실행 방법

```bash
npm install          # 루트에서 한 번 (workspaces로 server/client 모두 설치)
npm run dev           # server(4000)와 client(5173)를 동시에 실행
```

브라우저에서 http://localhost:5173 접속. (`/api` 요청은 vite dev 서버가 4000번으로 프록시)

개별 실행: `npm run dev:server`, `npm run dev:client`

## 주요 기능

### 1. 프로젝트 관리
- 목록 페이지에서 프로젝트 이름/설명을 입력해 생성, 삭제
- 상세 페이지 제목을 클릭하면 그 자리에서 이름을 바로 수정 가능 (별도 폼 없음)
- 프로젝트를 생성/이름 변경/삭제하면 서버가 대응하는 CSV 파일도 함께 생성/이름 변경(rename)/삭제

### 2. 프로젝트별 CSV 파일 저장
- 각 프로젝트의 작업은 `server/data/tasks/<프로젝트명>.csv`에 별도 파일로 저장됩니다 (요청하신 "프로젝트 파일별로 CSV 저장, 프로젝트명을 파일명으로" 반영).
- 프로젝트명이 중복되면 Windows 탐색기 방식으로 `이름 (2).csv`처럼 자동으로 구분됩니다.
- 파일명에 쓸 수 없는 문자(`\ / : * ? " < >` 등)는 `_`로 치환하고, 공백/하이픈은 그대로 유지합니다.
- 프로젝트 이름을 변경하면 기존 CSV 파일이 새 이름으로 **rename**되어 작업 데이터는 그대로 유지됩니다.
- 프로젝트를 삭제하면 해당 CSV 파일도 함께 삭제됩니다.
- 상세 페이지 상단에 현재 저장 파일 경로(`data/tasks/...`)가 항상 표시됩니다.
- `projects.csv`에는 각 프로젝트가 어느 파일을 쓰는지 기록하는 `taskFile` 컬럼이 있어, 이름이 같은 프로젝트가 여러 개 있어도 서로 다른 파일을 안전하게 구분합니다.

### 3. WBS(계획/실행 일정, 지연 표시)
- 각 작업 행에 계획 막대(위, 연한색 테두리)와 실행 막대(아래, 상태별 색상)를 함께 표시하는 커스텀 간트 뷰
- 오늘 날짜 칸은 전체 행 높이에 걸쳐 옅은 붉은 배경 + 양옆 테두리로 강조 표시 (칸 하나를 통째로 하이라이트, 값이 겹치지 않도록 헤더 표시 단위와 무관하게 항상 일 단위로 표시)
- 주말(토/일)은 타임라인 배경이 옅은 회색으로 구분되고, 월이 바뀌는 경계에는 굵은 세로선이 표시됨 (헤더 표시 단위와 무관하게 항상 일 단위로 표시되어, 주/월 단위로 축소해도 계속 보임)
- 지연된 작업은 진행 상태 배지에 ⚠ 표시, 계획 막대 테두리가 붉게 강조됨

### 4. 날짜 범위 확대/축소/이동
WBS 상단 컨트롤 바에서 조정합니다.
- **확대/축소**: `−` / `+` 버튼으로 "현재 기간 단위 한 칸"의 픽셀 폭을 7단계(20~88px)로 조절, `초기화`로 기본값(26px) 복귀. 예를 들어 기간 단위가 "일"이면 하루 칸이, "주"면 한 주 칸이, "월"이면 한 달 칸이 그 폭이 되도록 하루당 픽셀 폭이 자동으로 다시 계산됨 — 즉 "주"로 바꾸면 하루 칸은 1/7만큼 좁아지고, 그만큼 화면에 더 많은 날짜가 한 번에 들어옴 (기간 단위를 바꿔도 같은 화면 너비를 유지하려는 목적). 하단 한계를 20px로 둔 것은 "일" 단위에서 이 폭 밑으로 내려가면 두 자리 날짜 숫자(예: "31")가 옆 칸과 겹치기 때문
- **기간 단위(일/주/월)**: 헤더를 일별/주별/월별 칸으로 묶어서 표시할지 전환. 표시 중인 전체 기간이 60일 이하면 "일", 210일 이하면 "주", 그보다 길면 "월"이 초기값으로 자동 선택되고, 이후에는 버튼으로 언제든 직접 바꿀 수 있음 (기간을 넓혀도 자동으로 다시 바뀌지 않음). 위 확대/축소와 맞물려 동작하므로, 긴 기간을 좁게 보고 싶을 때 "주"나 "월"로 바꾸면 화면에 들어오는 날짜 범위 자체가 넓어짐. 막대·오늘 강조·주말/월경계 표시의 실제 위치 계산은 내부적으로 항상 일 단위 픽셀로 이뤄지므로(기간 단위에 따라 그 하루당 픽셀 값만 달라짐), 단위를 바꿔도 작업 데이터나 막대 위치 자체는 전혀 바뀌지 않음 — 화면에 보이는 칸 크기와 헤더 눈금 단위만 달라짐
- **이동**: `← 이전` / `다음 →` 버튼으로 현재 보이는 구간만큼 좌우로 스크롤 이동, 마우스/트랙패드 가로 스크롤도 그대로 사용 가능
- **오늘**: 오늘 날짜가 현재 표시 범위 밖에 있으면 범위를 자동으로 넓힌 뒤 화면 중앙으로 이동
- **기간(시작/종료) 직접 지정**: 두 날짜 입력을 바꾸면 그 구간으로 고정되고, `자동` 버튼으로 작업 일정 기준 자동 범위로 되돌릴 수 있음
- **열 표시**: 같은 컨트롤 바의 `열 표시` 드롭다운에서 상태/담당자/계획 일정/실행 일정/참조 링크/비고/진행 상태 열을 체크박스로 각각 숨기거나 다시 표시 가능 (작업명 열은 펼치기·수정·삭제 버튼을 포함하므로 항상 표시). 숨긴 만큼 표 너비가 줄어들어 타임라인을 더 넓게 볼 수 있음

### 5. 하위 작업 생성 및 드래그 앤 드롭 계층 조정
- 각 행의 `+` 버튼으로 하위 작업을 무한 depth로 생성
- 행을 마우스로 드래그해:
  - 행의 위쪽 28%에 놓으면 그 작업 **바로 위 형제**로 이동 (before)
  - 행의 아래쪽 28%에 놓으면 그 작업 **바로 아래 형제**로 이동 (after)
  - 행의 가운데 44%에 놓으면 그 작업의 **하위 작업**으로 이동 (inside, 자동으로 펼쳐짐)
- 자기 자신 또는 자신의 하위 작업으로 옮기는 순환 구조는 서버에서도 차단(400 에러)

### 6. 모달 없이 바로 수정 (인라인 편집)
아래 항목은 "수정" 버튼/모달을 거치지 않고 행에서 바로 바꿀 수 있습니다.
- **상태**: 행의 상태 배지가 곧 드롭다운 — 클릭해서 바로 변경
- **담당자**: 행의 담당자 칸을 클릭해 텍스트 입력, Enter 또는 포커스 아웃 시 저장
- **계획/실행 일정**: 각 칸의 날짜 입력을 바로 변경하면 즉시 저장
- **참조 링크 / 비고**: 각 칸을 클릭해 텍스트 입력, Enter 또는 포커스 아웃 시 저장. 참조 링크에 값이 있으면 옆에 ↗ 버튼이 나타나 새 탭에서 바로 열 수 있음 (`http://`/`https://`로 시작하지 않으면 여는 시점에 자동으로 `https://`를 붙임 — 저장되는 값 자체는 입력한 그대로 유지)
- **In Progress 작업의 실행 종료일 자동 표시**: 상태가 `in_progress`이고 실행 종료일을 아직 입력하지 않았다면, 실행 종료일 칸과 간트 막대에 "오늘 날짜"가 파란 이탤릭체로 자동 표시됩니다 (예: 아직 진행 중이니 오늘까지 진행된 것으로 간주). 이 값은 화면 표시용일 뿐 실제로 저장되지는 않으며, 날짜를 직접 선택해야 실제 실행 종료일로 저장됩니다. `done` 등 다른 상태에는 적용되지 않습니다.
- 작업명 변경, 작업/하위 작업 일괄 삭제 등은 기존처럼 ✎(수정) 모달에서 처리

### 7. 작업 상태 5종
`todo(Todo) / in_progress(In Progress) / in_review(In Review) / done(Done) / drop(Drop)`

### 8. 담당자
자유 텍스트 입력 (드롭다운 목록 없이 임의 문자열)

### 9. 참조 링크 / 비고
- **참조 링크**: 관련 문서/이슈/PR 등의 URL을 자유롭게 입력하는 텍스트 필드. 형식 검증은 하지 않으므로 URL이 아닌 텍스트도 저장은 되지만, 행에서 ↗ 버튼으로 열 때는 URL로 간주해 새 탭에서 엽니다.
- **비고**: 특이사항, 메모 등을 자유롭게 적는 텍스트 필드. 줄바꿈도 그대로 저장됩니다(CSV에는 큰따옴표로 감싸 이스케이프).
- 둘 다 작업 추가/수정 모달과 행 인라인 편집(위 6번) 양쪽에서 입력·수정할 수 있고, `열 표시`에서 숨길 수 있습니다.

### 10. 필터링 (상태 / 담당자 / 진행 상태)
툴바에 세 개의 다중 선택 필터가 있습니다.
- **상태 필터**: 위 5종 작업 상태 기준
- **담당자 필터**: 프로젝트 내 실제 사용된 담당자 목록 기준
- **진행 상태 필터**: 아래 "진행 상태별 판정 조건" 기준의 계산된 진행 상태 기준
- 필터에 맞는 작업과 그 **상위 경로만** 함께 표시되어 계층 구조가 끊기지 않고, 일치하지 않는 행은 흐리게(dim) 처리됩니다.
- 필터 적용 중에는 "N / 전체건 일치"가 표시됩니다.

### 11. CSV 파일 저장(내보내기) / 불러오기(가져오기)
프로젝트 상세 페이지 우측 상단의 두 버튼으로 사용합니다.
- **CSV 내보내기**: 현재 프로젝트의 작업 전체를 CSV 파일로 즉시 다운로드합니다 (`server/data/tasks/<프로젝트명>.csv`와 같은 형식 — `;` 구분자, 엑셀 호환을 위한 UTF-8 BOM 포함). 이 파일을 엑셀 등에서 편집한 뒤 다시 가져오기에 사용할 수 있습니다.
- **CSV 가져오기**: 파일을 선택하면 그 내용으로 **현재 프로젝트의 작업 전체를 교체**합니다(병합이 아님 — 기존 작업은 모두 사라지고 파일 내용으로 대체됩니다). 실행 전 확인 대화상자가 뜹니다.
  - 이 방식은 [CSV 파일을 직접 편집할 때 주의할 점](#csv-파일을-직접-편집할-때-주의할-점)에서 설명한 "서버가 켜진 채로 파일을 직접 고치면 편집 내용이 사라지는" 위험이 없습니다 — 서버를 끄고 켤 필요 없이 API를 통해 안전하게 반영됩니다.
  - 가져오기 시 전체 파일 단위로 아래 조건을 검증하며, 하나라도 위반하면 아무것도 바뀌지 않고 오류만 반환합니다(부분 반영 없음):
    - 모든 행에 `title`이 있어야 함
    - `id`가 비어 있으면 자동 생성되고, 값이 있으면 파일 내에서 고유해야 함
    - `parentId`는 비어 있거나(최상위) 같은 파일 안 다른 행의 `id`와 일치해야 함
    - `parentId` 순환 참조 금지 (예: A의 부모가 B, B의 부모가 다시 A)
    - `status`가 5종 값이 아니면 `todo`로 대체, 날짜 형식이 아니면 빈 값으로 대체 (에러는 아님)
    - `projectId` 컬럼 값은 무시되고 항상 현재 프로젝트 id로 강제 지정됩니다 (URL로 프로젝트가 이미 정해져 있으므로)

## 진행 상태별 판정 조건

작업의 "진행 상태"는 저장된 값이 아니라 **상태(status) + 계획일 + 실행일 + 오늘 날짜**를 기준으로 매 렌더링 시 계산됩니다 (`client/src/utils/schedule.ts`의 `computeScheduleStatus`). 판정은 위에서부터 순서대로 적용됩니다.

| 순서 | 진행 상태 | 조건 |
|---|---|---|
| 1 | **중단** (`dropped`) | 작업 상태가 `drop`인 경우 (다른 조건보다 우선) |
| 2 | **계획 미입력** (`no_plan`) | 계획 시작일 또는 계획 종료일이 비어 있는 경우 |
| 3 | **정상 완료** (`completed_on_time`) | 작업 상태가 `done`이고, 실행 종료일이 없거나 `실행 종료일 ≤ 계획 종료일`인 경우 |
| 4 | **지연 완료** (`completed_delayed`) | 작업 상태가 `done`이고, `실행 종료일 > 계획 종료일`인 경우 |
| 5 | **착수 지연** (`not_started_delayed`) | 위 done 케이스가 아니면서, `오늘 > 계획 종료일`이고 상태가 `todo`인 경우 **또는** 상태가 `todo`이고 `오늘 > 계획 시작일`인데 아직 실행 시작일이 없는 경우 |
| 6 | **실행 지연** (`in_progress_delayed`) | 위 done 케이스가 아니면서, `오늘 > 계획 종료일`이고 상태가 `todo`가 아닌 경우 (즉 `in_progress`/`in_review` 상태로 계획 종료일을 넘긴 경우) |
| 7 | **예정** (`scheduled`) | 위 지연 조건에 해당하지 않고, 상태가 `todo`인 경우 |
| 8 | **정상 진행** (`on_track`) | 위 지연 조건에 해당하지 않고, 상태가 `in_progress` 또는 `in_review`인 경우 |

날짜 비교는 `YYYY-MM-DD` 문자열을 그대로 사전순 비교합니다 (형식이 항상 0-패딩되어 있어 날짜 비교와 동일하게 동작).

배지 색상: 지연 계열(착수 지연/실행 지연/지연 완료)은 붉은색, 정상/완료 계열은 초록색, 예정은 파란색, 중단/계획 미입력은 회색으로 표시됩니다.

## REST API

모든 작업(Task) API는 프로젝트에 종속되어 `/api/projects/:projectId/tasks` 하위에 있습니다 (프로젝트별로 별도 CSV 파일을 쓰기 때문에 어느 파일을 읽고 쓸지 URL만으로 항상 명확하게 결정됩니다).

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/projects` | 프로젝트 목록 |
| POST | `/api/projects` | 프로젝트 생성 (`{name, description}`) — CSV 파일도 함께 생성 |
| PUT | `/api/projects/:id` | 프로젝트 이름/설명 수정 — 이름이 바뀌면 CSV 파일도 rename |
| DELETE | `/api/projects/:id` | 프로젝트 삭제 — CSV 파일도 함께 삭제 |
| GET | `/api/projects/:projectId/tasks` | 해당 프로젝트의 작업 목록 |
| POST | `/api/projects/:projectId/tasks` | 작업 생성 (`parentId` 생략 시 최상위) |
| PUT | `/api/projects/:projectId/tasks/:taskId` | 작업 필드 수정 (제목/상태/담당자/일정 등 부분 수정) |
| PATCH | `/api/projects/:projectId/tasks/:taskId/move` | 드래그 앤 드롭 이동 (`{parentId, orderIndex}`), 순환 구조는 400 |
| DELETE | `/api/projects/:projectId/tasks/:taskId` | 작업과 모든 하위 작업 삭제 |
| GET | `/api/projects/:projectId/tasks/export` | 현재 작업 전체를 CSV 파일로 다운로드 (`Content-Disposition: attachment`) |
| POST | `/api/projects/:projectId/tasks/import` | CSV 텍스트(`{csv: "..."}`)로 작업 전체를 교체(병합 아님), 검증 실패 시 400 |

## 데이터 형식

**열 구분자는 `,`가 아니라 `;`입니다** (`,`를 소수점으로 쓰는 로케일의 엑셀에서도 바로 깨끗하게 열리도록). 값에 `;`, 큰따옴표, 줄바꿈이 포함되면 RFC4180 방식대로 큰따옴표로 감싸 이스케이프합니다.
읽을 때는 첫 줄(헤더)에 `;`가 있는지로 구분자를 자동 판별하므로, 이 변경 이전에 `,`로 저장된 기존 CSV 파일도 계속 정상적으로 읽히며, 다음 저장 시점에 자동으로 `;` 형식으로 다시 저장됩니다(데이터 손실 없음).

`server/data/tasks/<프로젝트명>.csv` 컬럼:
`id; projectId; parentId; title; status; assignee; planStart; planEnd; actualStart; actualEnd; refLink; note; orderIndex; createdAt; updatedAt`

- 날짜는 `YYYY-MM-DD` 또는 빈 문자열
- `parentId`가 빈 문자열이면 최상위(root) 작업
- `refLink`, `note`는 자유 텍스트 (형식 검증 없음)
- `orderIndex`는 같은 부모를 가진 형제 간 정렬 순서(실수). 드래그 앤 드롭 시 이웃한 두 형제의 `orderIndex` 평균값으로 재계산되어, 대부분의 재정렬에서 다른 형제들의 순서 값은 그대로 유지됩니다.

#### `projectId` 지정 규칙

- 클라이언트가 직접 값을 넘길 수 없습니다. 항상 URL의 `:projectId`(`/api/projects/:projectId/tasks`)로 프로젝트가 먼저 확인되고, task를 생성할 때 서버가 `project.id`를 그대로 채워 넣습니다.
- 프로젝트마다 별도의 CSV 파일(`tasks/<프로젝트명>.csv`)을 쓰기 때문에, 한 파일 안의 모든 행은 항상 같은 `projectId`를 가집니다. 즉 이 컬럼은 "어느 파일에 속했는지"를 나타내는 부가 정보이며, 실제로 어느 파일을 읽고 쓸지는 URL만으로 결정됩니다.
- 존재하지 않는 `:projectId`로 요청하면 404(`project not found`)를 반환합니다.

#### `parentId` 지정 규칙

- 요청 본문의 `parentId`는 선택 값입니다. 생략하거나 문자열이 아니면 빈 문자열(`""`)로 처리되어 **최상위(root) task**가 됩니다.
- 값을 지정하면 **같은 프로젝트 안에 실제로 존재하는 task의 `id`**여야 합니다. 다른 프로젝트의 task id나 존재하지 않는 id를 지정하면 400(`invalid parentId`)이 반환됩니다 — 즉 task는 항상 자신이 속한 프로젝트 내부에서만 부모를 가질 수 있고, 프로젝트 경계를 넘는 계층 구조는 만들 수 없습니다.
- 이동(`PATCH /tasks/:taskId/move`) 시에는 추가로 두 가지 순환 방지 규칙이 적용됩니다:
  - 자기 자신을 부모로 지정할 수 없음 → 400(`a task cannot be its own parent`)
  - 자신의 하위(descendant) task를 부모로 지정할 수 없음(트리가 끊어지는 것을 방지) → 400(`cannot move a task into its own descendant`)
- 부모 task를 삭제하면 `parentId`로 연결된 모든 하위 task가 재귀적으로 함께 삭제됩니다(고아 행이 남지 않음).

#### CSV 파일을 직접 편집할 때 주의할 점

API를 거치지 않고 CSV 파일을 텍스트 에디터/엑셀 등으로 직접 열어 일정을 수정하는 것도 가능하지만, 서버가 로드 시점에 검증을 거의 하지 않으므로 아래 규칙을 지켜야 합니다. **아래 위험을 신경 쓰고 싶지 않다면, 대신 위 11번 "CSV 파일 저장/불러오기" 기능(상세 페이지의 `CSV 내보내기` → 엑셀 등에서 편집 → `CSV 가져오기`)을 쓰는 것을 권장합니다.** API를 거쳐 검증되고, 서버를 끄고 켤 필요도 없습니다.

- **반드시 서버를 끈 상태에서 편집할 것.** `CsvStore`는 파일을 최초 1회만 읽어 메모리에 캐시하고 이후로는 파일을 다시 읽지 않습니다(`server/src/store.ts`). 서버가 켜진 채로 파일을 직접 고치면, 그 뒤 API 호출이 한 번이라도 발생하는 순간 메모리에 있던 예전 상태로 파일 전체가 덮어써져 방금 한 수동 편집이 사라집니다. 편집 후에는 서버를 재시작하세요.
- **`id`는 사용자가 임의로 만들어도 됩니다.** 서버가 생성하는 값은 UUID v4이지만, 로드 시 형식 검증은 하지 않으므로 빈 문자열만 아니면 어떤 문자열이든 허용됩니다. 단, **같은 프로젝트 CSV 파일 안에서 고유해야** 합니다 — 중복되면 API의 `get`/수정/삭제가 모두 "처음 일치하는 행"만 대상으로 하여 동작이 뒤섞입니다.
- **`parentId`는 같은 파일 안 어떤 행의 `id`와 정확히 일치**해야 그 하위로 연결됩니다. 오타 등으로 일치하는 `id`가 없으면 에러 없이 조용히 최상위(root) task로 취급됩니다.
- **`status`도 형식 검증이 없습니다.** 반드시 `todo` / `in_progress` / `in_review` / `done` / `drop` 중 하나로 입력하세요. 다른 값을 넣으면 화면에서 상태 배지 색상/라벨을 찾지 못해 깨져 보일 수 있습니다.
- 날짜 칸은 `YYYY-MM-DD` 형식 또는 빈 문자열로 입력하세요 (API 경로로 들어오는 값과 달리 CSV 직접 편집 시에는 형식 검증이 없습니다).
- `orderIndex`는 숫자여야 하며, 같은 부모를 가진 형제 사이의 정렬 기준입니다. 비어 있거나 숫자가 아니면 `0`으로 처리됩니다.
- `projectId`는 실제 라우팅에는 쓰이지 않지만(어느 파일을 읽을지는 URL로만 결정됩니다), 혼동을 막기 위해 `server/data/projects.csv`에 있는 해당 프로젝트의 실제 `id`와 일치시켜 두는 것을 권장합니다.

`server/data/projects.csv` 컬럼: `id; name; description; createdAt; taskFile`
